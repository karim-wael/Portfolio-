# Local AI Workspaces: Running Offline LLMs with Ollama and Open WebUI

Developers frequently avoid third-party cloud LLM APIs when reviewing internal notes or private repositories due to privacy constraints and recurring API costs. Running open-weight quantized models locally solves this without external data egress.

## Setup Kit Architecture

**Chiggabot** (`Chiggabot_Setup_Kit`) is a practical Windows provisioning kit (`launch_agent.bat`, `download_models.ps1`, and `create_shortcut.ps1`) built to automate local LLM setup rather than maintaining a custom vector-store codebase:

```text
[launch_agent.bat] -> [Ollama Local Server :11434] + [Docker Open WebUI :8081] -> [Edge App Mode]
```

1. **Automated Model Provisioning (`download_models.ps1`)**: Pulls eight quantized local models (`tinyllama`, `phi3:mini`, `deepseek-r1:1.5b/14b`, `qwen2.5-coder:1.5b/14b`, `dolphin-llama3:8b`, and `llava:v1.6-7b`).
2. **Containerized Open WebUI (`docker`)**: Launches the Open WebUI container bound to port `8081` and connected via `host.docker.internal` to the local Ollama runtime, leveraging Open WebUI's built-in document Q&A capabilities offline.
3. **Zero Cloud Egress**: All prompts and uploaded files remain on local hardware (`localhost:8081`), eliminating third-party API exposure.
